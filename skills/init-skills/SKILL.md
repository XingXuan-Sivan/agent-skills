# Skills 环境初始化向导

## 概述

本 Skill 是一个**元技能（Meta Skill）**，帮助用户在任何 AI Agent 软件中快速初始化 Skills 环境。它不预先罗列固定的仓库清单，而是通过 [skills.sh](https://skills.sh) 聚合平台**实时检索**热门、高排名 Skills，结合用户实际需求进行**动态比对与推荐**，再由用户做出最终选择。

核心思路可以概括为：**skills.sh 发现 → 分层推荐 → 用户确认 → 执行安装**。

## 核心原则

1. **skills.sh 驱动发现**：所有 Skill 的检索、比对、推荐统一通过 skills.sh 聚合平台完成，不再维护静态的仓库源清单。skills.sh 汇聚了数万 Skills，提供热榜、排行榜、分类浏览等维度，可根据用户场景动态匹配
2. **不擅自决定**：任何安装操作前，必须向用户清晰说明推荐理由、给出具体建议，**等待用户明确同意后再执行**。绝不替用户做选择
3. **分层渐进**：按优先级分四层推进——核心元技能（必备）→ 文档处理（高频）→ 开发者必装（仅开发者）→ 按需实时推荐（个性化）
4. **安装级别首次确认，全流程沿用**：安装级别（全局 / 项目级）在首次涉及安装时与用户确认一次即可，后续推荐沿用此偏好，无需重复询问。若用户后续主动提出不同级别需求，再个别调整
5. **平台无关**：所有平台差异信息外置于 `references/platforms.md`，路径与命令通过运行时动态探测
6. **CLI 优先**：`npx skills` CLI 是安装工具，若环境不满足优先引导用户配置，仅当用户明确拒绝时才降级到手动方式
7. **自然语言交互，示例引导**：与用户的交互以自然语言为主，避免僵化的 `[1][2][A][B]` 编号选项堆砌。必要时可以用编号辅助展示以增加清晰度，但始终提供**示例回答**让用户知道如何回应，鼓励用户以开放方式描述需求。如果当前平台支持动态生成交互选项（如按钮、复选框），优先使用以提升体验
8. **灵活适配，拒绝死板**：推荐内容应根据用户实际需求和场景动态调整，而非机械罗列固定清单。推荐清单（`scenario-recommendations.json`）仅作参考基线，实际推荐时应结合 skills.sh 实时排行与用户具体情况灵活组合，不可照搬。同一决策不反复确认，但不同性质的新决策仍需征求用户意见
9. **重复安装检查**：安装任何 Skill 前，先通过 `npx skills list` 检查目标 Skill 是否已安装。若已安装，向用户说明其当前安装级别（全局/项目），询问是否需要调整级别（如从项目级提升到全局），若无需调整则跳过该 Skill，避免重复安装

## 执行流程

### 第零步：Skills CLI 环境准备（前置条件）

在执行任何安装操作之前，**必须先检查 `npx skills` CLI 是否可用**。

#### 环境检查

1. 检查 Node.js 是否安装（≥18）：执行 `node --version`
2. 检查 npm/npx 是否可用：执行 `npm --version`
3. 检查 `npx skills` CLI 是否可用：执行 `npx skills --help`

#### 环境不满足时的处理

若任一检查失败，向用户清晰说明缺失项并引导决策。**交互应自然灵活**，不要用死板的编号选项堆砌：

> ⚠ Skills CLI 环境不满足，当前缺失：
>   - Node.js ≥ 18：未安装 / 版本过低（当前版本：vX.X.X）
>   - npm/npx：未安装
>
> `npx skills` CLI 是 Skills 生态的包管理器，安装和管理 Skills 都会用到它。
>
> 我可以帮你自动配置 Node.js 环境——会根据你的操作系统选择合适的安装方式，完成后自动验证。当然，你也可以选择跳过 CLI，后续用 git clone 或手动下载 ZIP 的方式安装 Skill（会麻烦一些，且无法使用 skills.sh 的搜索和热榜功能）。
>
> 你希望怎么处理？
> （示例回答："帮我自动配置" / "先跳过，用手动方式" / "我自己装好了 Node，重新检测一下"）

- **用户同意配置**：按照 `references/platforms.md` 中对应操作系统的指引自动安装 Node.js，完成后执行 `npx skills --help` 验证可用性
- **用户拒绝配置**：尊重选择，跳过 CLI，后续安装使用 git clone 或 ZIP 方式，并在最终报告中提示 CLI 缺失的影响
- **用户有其他想法**（如自行安装、已安装但路径不对等）：灵活应对，不要僵化套用预设选项

### 第一步：平台检测

1. 询问用户当前使用的 Agent 软件，或通过工作区目录自动推断（`.qoder/`、`.claude/`、`.cursor/` 等）
2. 查阅 `references/platforms.md` 确认该平台的 Skills 目录路径
3. 记录平台信息（安装级别将在第一层推荐时与用户统一确认，后续全流程沿用）

### 第二步：了解用户需求

在推荐任何 Skill 之前，先简短了解用户的使用场景。交互应开放、自然，**不要把场景列举成死板的选项**，而是引导用户自由描述：

> 在开始推荐之前，我想先了解一下你的使用场景——你平时主要用 Agent 做什么呢？比如日常写文档、做前端开发、搞数据分析，或者多种场景混着来？另外，有没有你特别想优先安装的 Skill 类型，或者之前听说过哪个想试试的？
>
> （示例回答："我主要做前端开发，经常需要写文档和做PPT汇报" / "全栈开发，后端偏多，对 MCP 工具扩展比较感兴趣" / "暂时没什么特别偏好，先看看推荐"）

根据用户回答，标记后续推荐策略的侧重点和优先级。

### 第三步：分层渐进式安装

按以下四个层级依次推进，**每层安装前都需要用户确认**。每进入下一层前，报告当前层的安装结果。

---

#### Step 1/4：核心元技能（必备）

这是 Skills 生态的基石，强烈建议所有用户安装：

| Skill | 用途 | 重要性 |
|-------|------|--------|
| `find-skills` | 搜索与发现新 Skill，未来需要任何功能时可快速检索 | 🔴 必备 |
| `skill-creator` | 用 AI 创建自定义 Skill，满足个性化需求 | 🔴 必备 |

**推荐策略**：

用自然语言向用户介绍这两个 Skill 的价值，给建议但留足灵活性。**首次推荐时一并确认安装级别，后续全流程沿用**：

> 📌 Step 1/4：核心元技能
>
> 首先要介绍 Skills 生态的两个基石 Skill：
>
> - **find-skills**：当你想给 Agent 增加某个功能但不知道有没有现成的 Skill 时，它能帮你从 skills.sh 上快速搜索发现。可以说是一个"Skill 搜索引擎"
> - **skill-creator**：当你需要某个专属功能但实在找不到现成的，它能帮你用 AI 直接创建一个自定义 Skill，从零到可用一条龙
>
> 这两个几乎人人都会用到，我建议两个都装上。不过如果你已经有其中一个，或者想先试试水，只装一个也完全没问题。
>
> 另外关于安装位置——全局安装（`-g`）会让所有项目都能用，推荐核心 Skill 这样装；项目级安装则只对当前项目生效。你更倾向哪种？（选一次就行，后续推荐我会记住你的偏好，不再重复问）
>
> （示例回答："两个都装，全局" / "先装 find-skills 试试，项目级的" / "都装，但 find-skills 全局，skill-creator 项目级" / "先跳过，后面再说"）

**安装方式**：

用户确认后，通过 skills.sh 检索获取实际安装源，再执行安装：

0. 先执行 `npx skills list` 检查目标 Skill 是否已安装；若已安装，告知用户当前安装级别并询问是否需要调整，无需调整则跳过
1. 使用 `npx skills find <name>` 或访问 skills.sh 搜索对应 Skill 的最新可用源
2. 执行 `npx skills add <source>@<name> -g`（或去掉 `-g` 进行项目级安装）
3. 若 CLI 不可用，参照 `references/platforms.md` 降级为 git clone / ZIP

安装完成后，简要报告结果，然后询问是否进入下一层。如果用户在第二层及之后不主动提出更改，安装级别沿用第一层的选择。

#### Step 2/4：文档处理 Skills（高频推荐）

这是日常办公中使用频率最高的一类 Skill：

| Skill | 用途 | 典型场景 |
|-------|------|---------|
| `docx` | Word 文档创建与编辑 | 报告、简历、合同 |
| `pdf` | PDF 处理（提取、合并、转换、OCR） | 阅读文献、表单处理 |
| `xlsx` | Excel 表格处理与数据分析 | 数据报表、CSV 处理 |
| `pptx` | PowerPoint 演示文稿创建 | 答辩、汇报、演讲 |

**推荐策略**：

根据第二步了解的用户场景，**有侧重地推荐**，而非机械罗列全部四个。结合用户场景说明哪些最匹配、哪些可能用不上，让用户自主勾选：

> 📌 Step 2/4：文档处理 Skills
>
> 根据你之前提到的场景（XXX），文档处理类里这几个可能对你有用：
>
> - **docx**：Word 文档的创建和编辑，写报告、做简历、整合同都很方便
> - **pdf**：PDF 的提取、合并、转换，看文献、填表单的利器
> - **xlsx**：Excel 表格处理，做数据报表、处理 CSV 都靠它
> - **pptx**：PPT 演示文稿，答辩、汇报、演讲一键生成
>
> 结合你的场景，我建议至少装 XXX 和 XXX，其余按需。你觉得哪些对你有用？
>
> （示例回答："全都要" / "docx 和 pdf 就够了" / "先装 docx，其他以后再说" / "先跳过这一层"）
>
> 安装级别沿用你之前选的全局（或项目级），如果有哪个想单独调整告诉我即可。

用户确认后，通过 skills.sh 检索对应 Skill 的最新安装源，逐一执行安装。安装前执行重复检查，已安装的不再重复安装。**不再重复询问安装级别**（除非用户主动提出调整）。

#### Step 3/4：开发者必装 Skills（仅面向开发者）

如果用户在第二步中表明自己是开发者或涉及开发相关任务，则在此步骤中优先推荐以下开发者必装 Skills。若用户场景完全不涉及开发，则直接跳过本层进入 Step 4/4。

| Skill | 用途 | 重要性 |
|-------|------|--------|

| `improve-codebase-architecture` | 分析并改进现有代码库的架构设计，提升可维护性、可扩展性与代码质量 | 🟡 推荐 |

**推荐策略**：

> 📌 Step 3/4：开发者必装 Skills

>
> - **superpowers**：这是开发场景的"必备元技能套件"，安装后会自动包含 `using-superpowers` 等一整套子技能。它能让 Agent 在每次开发对话中自动建立技能发现与使用机制，大幅提升协作效率。**建议在开发任务时将 `using-superpowers` 注入上下文以激活整套技能**。默认安装整套（包含所有子技能），除非你明确说只想装其中某个
> - **frontend-design**：帮你做出独特、有品味的前端界面设计，无论是新项目搭建还是旧界面翻新都适用

> - **improve-codebase-architecture**：代码架构层面的"体检+优化"，帮你分析现有代码结构问题并给出改进方案

>
> 安装级别沿用之前的偏好，有需要调整的单独说。
>
> （示例回答："六个都要" / "superpowers + vue-best-practices + agent-browser" / "只要 superpowers" / "先跳过这一层"）

**安装方式**：

用户确认后，通过 skills.sh 检索获取实际安装源，再执行安装。`superpowers` 默认安装整套（包含所有子技能），除非用户明确要求只安装其中某个子技能。安装前执行重复检查，已安装的不再重复安装。

#### Step 4/4：按需实时推荐（个性化）

这一层不再依赖静态清单，而是**实时访问 skills.sh**，综合以下维度为用户检索和推荐：

- **热榜（Trending）**：当前社区最活跃、增长最快的 Skills
- **排行榜（Top Rated）**：长期高评分、经过大量用户验证的 Skills
- **分类浏览**：按用户场景对应的分类（通用办公 / 创意设计 / 部署运维 / 浏览器自动化等）定向检索
- **关键词搜索**：根据用户第二步中提到的具体需求精确匹配

**执行步骤**：

1. **访问 skills.sh**，获取当前热榜和排行榜数据，提取排名靠前的高质量 Skills
2. **交叉比对**：将热榜/排行榜结果与用户需求场景交叉筛选，挑选出 5-8 个最相关的候选 Skill
3. **展示推荐**：列出候选 Skill，每个注明以下信息：
   - Skill 名称与一句话描述
   - 来源（skills.sh 排名 / 热榜位置 / Star 数）
   - 推荐理由（如何匹配用户场景）
   - 质量信号（更新频率、维护状态）
4. **引导选择**：让用户自主表达感兴趣的方向或具体 Skill，而非强制按照编号勾选
5. **执行安装**：用户确认具体选择后，通过 `npx skills add` 安装

**交互风格**：

推荐时保持自然对话感，做好引导但不僵化。当前平台如果支持动态生成按钮/复选框等交互组件，优先使用。纯文本输出时，务必提供示例回答：

> 📌 Step 4/4：按需实时推荐
>
> 我已在 skills.sh 上结合热榜和你的场景（XXX）做了一轮筛选，以下 6 个 Skill 比较值得关注：
>
> - **frontend-design**（🏆 热榜 #3，⭐ 2.1k）：高质量 UI 与前端设计，和你做前端开发的场景非常契合
> - **mcp-builder**（🏆 热榜 #8，⭐ 1.5k）：构建 MCP 服务端来扩展 Agent 工具能力，如果你想让 Agent 接入外部 API 或数据库会很实用
> - **webapp-testing**（📈 上升最快，⭐ 980）：用浏览器自动化做 Web 应用测试，和前端开发是天然搭档
> - ...（更多候选，标注排名和推荐理由）
>
> 上面这些你觉得哪个对胃口？可以挑几个感兴趣的，或者说说你更想要哪类功能，我帮你进一步搜。不用拘泥于编号，直接说名字或者描述需求都行。
>
> （示例回答："frontend-design 和 mcp-builder 都要" / "有数据库相关的吗？帮我搜一下" / "先装前两个，后面的再说" / "这一层先跳过"）
>
> 安装级别沿用之前的偏好，有需要调整的单独说。

> **注意**：如果用户在第二步中表露的需求非常具体，也可以直接用 `npx skills find <keyword>` 精准搜索，同时交叉参考 skills.sh 的评分数据作为质量佐证。推荐时不可机械照搬推荐清单，应根据用户实际需求、技术栈和 skills.sh 实时排行灵活组合，综合推荐。如果当前平台支持 `AskUserQuestion` 等动态交互组件，优先使用来展示选项，提升交互体验。

### 第五步：CLI 常用命令速查

在报告末尾附上常用命令参考。若用户在本次初始化中配置了 CLI 环境，这部分作为"上手引导"；若未配置 CLI，作为"未来参考"：

```
## npx skills CLI 常用命令

`npx skills` 是 Skills 生态的包管理器。常用命令如下：

### 查找 Skills
  npx skills find <keyword>        # 按关键词搜索 Skill
  示例：npx skills find database   # 搜索数据库相关 Skills

### 安装 Skills
  npx skills add <owner>/<repo>@<name>       # 安装指定 Skill（项目级）
  npx skills add <owner>/<repo>@<name> -g    # 全局安装
  示例：npx skills add anthropics/skills@docx -g

### 查看已安装
  npx skills list                  # 列出所有已安装的 Skills

### 初始化项目
  npx skills init                  # 在当前项目创建 Skills 目录

### 获取帮助
  npx skills --help                # 查看完整命令列表

### skills.sh 平台
  浏览器访问 https://skills.sh —— 浏览热榜、排行榜、按分类检索 Skills
```

若 CLI 未配置，额外提示：
> 以上 CLI 命令需要 Node.js 环境。你可随时重新运行本 Skill 配置 CLI，或参考 `references/platforms.md` 中的环境配置指南。skills.sh 平台则无需 CLI，浏览器直接访问即可。

## 安装方式（多级降级）

按照以下优先级：

1. **`npx skills` CLI**（首选）：支持 search、add、list、init 等完整功能。若环境不满足，优先引导用户自动配置
2. **`git clone`**（CLI 不可用且用户拒绝配置时）：克隆仓库后手动复制 Skill 目录
3. **手动 ZIP 下载**（兜底）：提供下载链接和手动安装指引

具体的命令和路径见 `references/platforms.md`。

## 安全提醒

在安装任何第三方 Skill 前，提醒用户注意：
- skills.sh 聚合平台上的 Skill 来自公开 GitHub 仓库，安装前建议查看其 Star 数、更新频率和社区反馈
- 优先选择 skills.sh 上排名靠前、更新活跃的 Skill
- 安装前通读 SKILL.md，确认操作范围在预期之内
- 避免使用超过 6 个月未更新的 Skill
- 详细安全评估指南见 `references/security.md`
