# 索引与导航的自动生成

## 原则

**索引是 frontmatter 的投影，不是另一份需要维护的数据。**

每篇文档的 `title`、`summary`、`status` 已经描述了它自己；索引表只是把这些字段汇总起来。
所以索引**默认由生成器产出**，人工维护只作为兜底。

人工手写索引的实际结局是：文档改了、索引忘了改，然后没有人再相信索引。

## 生成区约定

索引写在目录 `README.md` 里，用 HTML 注释标记出生成范围：

```markdown
本目录收录项目必须遵守的约定。

<!-- gen:docs:start -->
| 文档 | 一句话 | 状态 |
|---|---|---|
| [通用开发规范](universal.md) | 架构、配置、注释与交付质量 | active |
<!-- gen:docs:end -->
```

- **标记之外**的内容由人维护，生成器不碰。
- **标记之内**的内容每次生成时整体重写。
- 两个可用区块：`gen:docs`（本目录的文档表）、`gen:subdirs`（直接子目录表）。按需使用，不强制都有。

## 命令

```bash
# 生成（写入）
python scripts/gen_index.py <项目根目录>

# 只检查是否同步，不写入；不同步返回退出码 1
python scripts/gen_index.py <项目根目录> --check
```

`verify_docs.py` 会在 `gen_index.py` 同目录存在时自动带上这项检查，所以日常只需要跑前者。

**把 `--check` 挂进 CI 或提交前钩子**，这样「文档改了忘记重新生成」不再依赖谁记得。

## 生成规则

| 区块 | 数据来源 | 排序 |
|---|---|---|
| `gen:docs` | 同目录下非 `README.md` 的每篇文档 | 文件名 |
| `gen:subdirs` | 直接子目录，取其 `README.md` 标题后的第一段作为职责 | 目录名 |

因此有两条写作约定：

1. 每篇文档必须有 `title` 与 `summary`——它们就是索引里的两列。
2. **目录 `README.md` 的标题之后第一段，必须是一句话职责**，上级目录的索引会引用它。

被引擎豁免或列入「不纳入索引的目录」的目录，不参与生成。

## 人工兜底的边界

只有两种情况才手写索引：

- 用户在明确要求中指定要手写
- 项目尚未引入生成器，正在迁移过程中

即使手写，也必须遵守「不建占位文档」与「每篇文档都能从所属目录到达」两条规则。
