# Java 后端编码规范

## 分层与组织

- 包按能力与领域组织，避免把所有类型按 Controller、Service、Repository 横向堆放。
- 统一 Controller 与 Service 层的方法命名及 API 设计，特别是 CRUD 操作，确保不同对象的增删改查在命名风格、参数格式与 API 路径结构上保持一致，形成清晰一致的开发约定。

## 依赖与配置

- 必需依赖使用构造器注入并保持 `final`。
- 配置使用类型安全的绑定方式；不要在业务代码中重复读取环境变量。
- 权限、路径、配置前缀和状态名称由统一常量或契约定义。

## 契约

- 公共 API 使用 DTO 或不可变视图，不向外暴露持久化内部结构。
- 扩展点通过公开接口接入，不反向依赖宿主内部实现。

## 日志

- 使用参数化消息，不记录密码、Token、Secret 或完整敏感正文。
- 日志信息使用中文。

## 运行边界

- 生产模式保持 fail-closed；新增的开发便利必须被 Profile 或明确的启动入口隔离。
- 文件系统操作必须经过受管根目录和路径边界检查。

## 注释

- 注释解释约束和意图，不记录作者、修改历史或任何可由版本控制获取的信息。
- 注释使用中文。
